# Playbook: клиентские опросы в Testograf (PRO+)

Операционная инструкция для тех, кто собирает опросы в [Testograf](https://www.testograf.ru/).  
Типы опросов: **NPS, CSI, CSAT, голосования, послесервисные**.

Презентация: [`docs/Testograf_playbook_client_surveys.pptx`](Testograf_playbook_client_surveys.pptx)  
(пересборка: `python3 nps_pipeline/build_testograf_playbook_pptx.py` → файл также в `nps_pipeline/build/`, каталог в gitignore).

Документ отвечает на вопросы: *зачем настройка*, *где включить*, *когда включать / выключать*, *какие риски*, *как чистить данные после сбора*.

---

## 1. Как мы работаем с опросами

Обязательный порядок запуска. Нельзя публиковать ссылку респондентам, пока не пройдены шаги 1–9.

| Шаг | Действие | Ответственный | Важно |
| --- | --- | --- | --- |
| 1 | Приходит заказчик с готовым брифом. Если заказчик — мы сами, бриф готовим сами | Инициатор / аналитик | В брифе: цель, ЦА, каналы, сроки, квоты, нужен ли 1 ответ на человека |
| 2 | Заводим опрос в Testograf | Ответственный за опрос | Конструктор: Создание → Логика → Настройка → Дизайн |
| 3 | **Отключаем** ограничение на повторное прохождение | Ответственный за опрос | Нужно, чтобы внутренняя команда и заказчик могли многократно тестировать |
| 4 | Отдаем внутренней команде на проверку логики и ошибок | Внутренняя команда | Проверяют ветвления, обязательность, тексты, мобильный вид |
| 5 | После внутренней проверки — на проверку заказчику | Ответственный за опрос | Фиксируем список правок |
| 6 | Параллельно готовим коммуникацию об опросе | Коммуникации / маркетинг | Текст push / ТГ / email / ЛК — в тон с брифом |
| 7 | Опрос **и** коммуникационное сообщение согласовывает руководитель департамента маркетинга **Голубева Екатерина Анатольевна** | Руководитель департамента маркетинга | Без этого согласования запуск запрещен |
| 8 | Ответственный **зачищает тестовые ответы**, затем **включает** ограничение повторного прохождения (нельзя пройти дважды) | Ответственный за опрос | См. раздел 3.1 и 5 |
| 9 | Запуск | Ответственный за опрос | Включаем период проведения, публикуем каналы, фиксируем дату старта |

### Правило про ограничение повторов

- **На этапах 3–7** ограничение **выключено**: иначе тестировщики и заказчик не смогут пройти сценарии повторно.
- **На шаге 8, перед запуском** ограничение **включается** (по умолчанию — с устройства / cookies; для строгих кейсов — персональные ссылки или SMS, см. карточки ниже).
- Если после запуска нашли критичный баг: снова выключить ограничение → починить → зачистить тестовые ответы → снова включить → продолжить сбор.

## 2. Типы опросов и цели качества

| Тип | Цель | Главные риски нерепрезентативности | Приоритет защиты |
| --- | --- | --- | --- |
| **NPS** | Индекс лояльности 0–10, динамика, сегменты | Повторы, незавершенные, «случайные» клики, малые n по ЖК | Высокий: 1 человек = 1 ответ; только завершенные |
| **CSI** | Удовлетворенность по факторам / услугам | Straight-line по матрицам, пропуск важных блоков | Высокий: обязательные ключевые шкалы; логика дисквалификации нецелевой ЦА |
| **CSAT** | Оценка конкретного касания (после заявки, визита) | Дубли после повторных касаний; слишком поздний/ранний опрос | Средний/высокий: персональная ссылка или параметр сделки; тайминг коммуникации |
| **Голосование** | Выбор варианта (дизайн, название и т.п.) | Накрутки, боты, несколько голосов с разных устройств | Максимальный: SMS / персональные ссылки; без показа промежуточных итогов |
| **Послесервисный** | Обратная связь по обращению | Не та ЦА, повторные оценки одного кейса | Высокий: параметр ID обращения; дисквалификация «не обращался» |

## 3. Карточки настроек Testograf

Где искать большинство опций: конструктор → вкладка **«Настройка»** → **«Основное»** (блок «Вход» и др.).  
Логика: вкладка **«Логика»** / **«Продвинутая логика»** (PRO+).

### 3.1. Ограничение повторного прохождения (устройство / cookies)

| | |
| --- | --- |
| **Зачем** | Один респондент — один ответ. Снижает случайные и намеренные дубли |
| **Где** | Настройка → Основное → блок «Вход» → ограничение повторного заполнения с устройства (cookies). Можно задать число раз и период |
| **Когда включать** | Перед боевым запуском (наш шаг 8). Всегда для NPS / CSI / CSAT / голосований / послесервиса, если нет персональных ссылок |
| **Когда выключать** | На этапах тестирования и согласования (наш шаг 3). Временно — при срочном фиксе после запуска |
| **Риски** | Легко обойти: инкогнито, другой браузер/устройство, очистка cookies |
| **Постобработка** | Дедуп по ID респондента / параметру ссылки / телефону / email, если собирали |

### 3.2. Ограничение по IP

| | |
| --- | --- |
| **Зачем** | Умеренная защита от накруток без авторизации |
| **Где** | Настройка → Основное → блок «Вход» → ограничение по IP |
| **Когда включать** | Открытые голосования с риском накрутки; массовые открытые ссылки без перс. ссылок |
| **Когда выключать** | Опросы жителей одного ЖК / офиса / Wi‑Fi; корпоративные сети; мобильные операторы с общим NAT. **Для наших NPS жителей ЖК — обычно выкл.** |
| **Риски** | Один IP = много честных людей → потеря ответов |
| **Постобработка** | Смотреть всплески с одного IP в выгрузке, если IP доступен |

### 3.3. Персональные / одноразовые ссылки и параметры ссылки

| | |
| --- | --- |
| **Зачем** | Максимальный контроль «кто ответил»; нельзя пройти повторно даже с другого устройства; сегментация (ЖК, фонд, канал) |
| **Где** | Параметры ссылки: «+ Значения» → мульти-загрузка → «Скачать ссылки»; опция ограничить повтор по параметру. Email/SMS-рассылка Testograf: «Запретить повторное заполнение», «Идентификация ответа». На PRO+ до **50** параметров ссылки |
| **Когда включать** | CSAT после конкретного обращения; закрытые панели; когда список email/телефонов известен; NPS с раздачей по ЛК с ID |
| **Когда выключать** | Широкая открытая ссылка в ТГ / QR без списка участников |
| **Риски** | Пересылка ссылки другому человеку; ошибка в параметрах → кривая сегментация |
| **Постобработка** | Фильтр по валидным значениям параметров (периметр ЖК и т.п.); отсев пустых/битых ID |

### 3.4. Пароль (общий / индивидуальный)

| | |
| --- | --- |
| **Зачем** | Закрытый доступ; индивидуальный пароль ≈ один проход + идентификация в результатах |
| **Где** | Настройка → Основное → «Доступ по паролю» → общие или индивидуальные пароли → «Идентификация ответа» → загрузка паролей |
| **Когда включать** | Закрытые голосования; пилоты; когда нельзя светить открытую ссылку |
| **Когда выключать** | Массовые клиентские опросы через ЛК / push (лишний барьер → падение response rate) |
| **Риски** | Утечка общего пароля = накрутка; забытый пароль = потеря ответов |
| **Постобработка** | Сверять ответы с выданным списком паролей |

### 3.5. SMS-подтверждение ответа (PRO+)

| | |
| --- | --- |
| **Зачем** | Один номер — один подтвержденный ответ; защита голосований от ботов |
| **Где** | Настройка → Основное → Дополнительно → подтверждение через SMS (нужен кабинет SMS Профи; оплата SMS отдельно) |
| **Когда включать** | Голосования с риском накрутки; спорные публичные выборы |
| **Когда выключать** | NPS/CSI жителей (лишний friction); короткие CSAT; аудитория без готового мобильного сценария |
| **Риски** | Отказ на финале; стоимость SMS; до 5 попыток кода, затем блокировка |
| **Постобработка** | Только подтвержденные ответы считаются валидными |

### 3.6. Сохранение незавершенных ответов (PRO+) — «оборванные» прохождения

| | |
| --- | --- |
| **Зачем** | Респондент может вернуться и дописать длинный опрос; в ЛК видно, где бросили |
| **Где** | Настройка → Основное → сохранение незавершенных ответов |
| **Когда включать** | Длинные NPS/CSI (много страниц); заполнение в несколько заходов с именной ссылкой / паролем |
| **Когда выключать** | Короткие CSAT (1–3 вопроса); голосования «один клик»; если в аналитику нельзя пускать частичные |
| **Риски** | Частичные ответы попадут в выгрузку с пометкой «Незавершен»; уникальную ссылку нельзя пересылать — откроют чужой черновик |
| **Постобработка** | **В метрики NPS/CSI/CSAT брать только завершенные** (`NOT_COMPLETED == 0` или аналог). Незавершенные — отдельно для диагностики drop-off |

### 3.7. Рандомизация страниц / вопросов / ответов («блуждающий» порядок)

В UI Testograf это **случайный порядок** (рандомизация), а не отдельная кнопка «блуждающие ответы».

| | |
| --- | --- |
| **Зачем** | Снять эффект порядка: первый вариант не получает лишних голосов; матрицы не «заучиваются» сверху вниз |
| **Где** | На уровне страницы: случайный порядок вопросов. На уровне вопроса: случайный порядок вариантов ответов. (Страницы — при необходимости в структуре опроса) |
| **Когда включать** | Списки равноправных брендов/опций; длинные матрицы CSI; A/B без фиксированного порядка; голосование за равнозначные варианты |
| **Когда выключать** | Шкалы NPS 0–10 и Лайкерт (порядок шкалы должен быть фиксированным!); логические последовательности («сначала факт, потом оценка»); вопросы с ветвлением, завязанным на конкретный порядок; инструкции «прочитайте сверху вниз» |
| **Риски** | При включенной рандомизации + сложной логике сложнее тестировать; в отчете порядок вариантов может отличаться от «привычного» |
| **Постобработка** | На метрики не влияет, если кодировки ответов стабильны по ID, а не по позиции на экране |

**Практическое правило для нас**

- NPS-шкала 0–10 — **рандомизацию ответов выключить**.
- Варианты «что улучшить» / мультивыбор факторов — **рандомизацию вариантов включить**, если нет жесткой бизнес-сортировки.
- Страницы с логической историей (профиль → NPS → причины) — **рандомизацию страниц выключить**.

### 3.8. Обязательность вопросов

| | |
| --- | --- |
| **Зачем** | Не терять ключевые поля (NPS, ЖК, CSAT); снижать «пустышки» |
| **Где** | В карточке каждого вопроса: обязательный / необязательный |
| **Когда включать** | Все ключевые метрики и поля сегментации (NPS, CSI-индексы, ID ЖК, факт обращения) |
| **Когда выключать** | Чувствительные и открытые комментарии (чтобы не потерять весь ответ из‑за одного поля); второстепенные блоки |
| **Риски** | Слишком много обязательных → рост отказов на середине |
| **Постобработка** | Ответы без ключевой метрики — в брак, даже если статус «завершен» |

### 3.9. Таймер вопроса / опроса

| | |
| --- | --- |
| **Зачем** | Ограничить время на тест/задание; ускорить короткие голосования |
| **Где** | Таймер вопроса — в настройках вопроса. Таймер опроса — Настройка → Параметры |
| **Когда включать** | UX-тесты, квизы, задания с лимитом времени |
| **Когда выключать** | **Почти всегда для NPS/CSI/CSAT жителей** — давление по времени дает случайные клики |
| **Риски** | «Блуждающие» быстрые ответы, рост incomplete |
| **Постобработка** | Если таймер все же был: смотреть долю автопереходов / слишком короткое TOTAL |

### 3.10. Логика, дисквалификация, индивидуальные завершения

| | |
| --- | --- |
| **Зачем** | Не смешивать целевую и нецелевую аудиторию; разные сценарии («не живет в ЖК» → выход без NPS) |
| **Где** | Вкладка «Логика»; PRO+: «Продвинутая логика» (И/ИЛИ, параметры ссылки, матрицы) |
| **Когда включать** | Скринер ЦА; ветки «пользовался услугой / не пользовался»; квоты качества |
| **Когда выключать** | Нет нецелевой аудитории; простой одностраничный CSAT |
| **Риски** | Ошибка в условии → все уходят в дисквал или мимо нужных вопросов. Обязателен прогон всех веток на шаге 4 процесса |
| **Постобработка** | Дисквалифицированных **не включать** в базу NPS/CSI; вести отдельно счетчик «отсеяно скринером» |

### 3.11. Квотирование

| | |
| --- | --- |
| **Зачем** | Не перекосить выборку (регион, ЖК, сегмент) |
| **Где** | Квоты на ответы / на весь опрос (функционал квотирования в конструкторе) |
| **Когда включать** | Исследования с целевой структурой выборки; платные панели |
| **Когда выключать** | Сплошной опрос всех жителей канала; когда важнее максимальный n, чем баланс |
| **Риски** | Раннее закрытие квоты → недобор редких сегментов |
| **Постобработка** | Сверять факт vs план квот; взвешивание — только по отдельному методологическому решению |

### 3.12. Рассылки email / SMS, виджет, QR

| | |
| --- | --- |
| **Зачем** | Доставить опрос и напоминания; повысить доходимость |
| **Где** | Раздел сбора ответов опроса: email-рассылка, SMS (PRO+, через SMS Профи), ссылка, QR, виджет |
| **Когда включать** | Email/SMS — при базе контактов; виджет — на сайте после действия; QR — офлайн/подъезд |
| **Когда выключать** | Дублирующие каналы без контроля → двойные прохождения (если слабая защита повторов) |
| **Риски** | Лимиты PRO+: до 15 000 писем/сутки; SMS платные; пересечение каналов |
| **Постобработка** | Дедуп между каналами по ID / телефону / параметру |

### 3.13. Показ результатов респонденту / публичная ссылка на итоги

| | |
| --- | --- |
| **Зачем** | Прозрачность голосования; обучение |
| **Где** | Настройка → Основное → показ результатов; публичная ссылка на результаты |
| **Когда включать** | После закрытия голосования — по решению заказчика |
| **Когда выключать** | **Во время сбора** NPS/CSI/CSAT и конкурентных голосований — иначе ответы подстраивают под лидера |
| **Риски** | Бандвагон-эффект |
| **Постобработка** | Не требуется |

### 3.14. API и веб-хуки (PRO+)

| | |
| --- | --- |
| **Зачем** | Автовыгрузка в витрины/CRM; realtime-обновления |
| **Где** | ЛК → API (токен); веб-хуки в настройках интеграции; base `https://core.testograf.ru/api/private/v1` |
| **Когда включать** | Регулярные NPS с пайплайном; интеграции |
| **Лимиты** | **120 запросов/мин**, **500 запросов/сутки** на пользователя лицензии; расширение через поддержку |
| **Риски** | HTTP 429; ключ в открытом виде; на PRO+ веб-хук может слать каждый ответ сразу |
| **Постобработка** | Те же правила фильтрации, что и для ручной выгрузки; не публиковать `.env` и ключи |

## 5. Постобработка: как отсекать плохие и нерепрезентативные ответы

Делать **после закрытия волны** (или по расписанию синка), до публикации индексов.

### 5.1. Базовый фильтр (обязателен для NPS/CSI/CSAT)

1. Удалить / не учитывать **тестовые** ответы (служебные прогоны команды и заказчика). Перед запуском — зачистка в ЛК Testograf (шаг 8 процесса).
2. Только **завершенные** анкеты (`NOT_COMPLETED == 0` или статус без «Незавершен»).
3. Отсечь явные техзаписи (например, первая служебная `SERIAL_NUM`, если так принято в проекте).
4. Валидный ключ сегментации (ЖК из утвержденного периметра и т.п.).
5. Часовой пояс учета — **MSK (UTC+3)**.

### 5.2. Скоростные и «блуждающие» ответы (satisficing)

Признаки:
- аномально короткое время прохождения относительно медианы;
- одна и та же позиция по всей матрице (straight-line);
- противоречия (например, NPS = 10 и в открытом «все ужасно» — решать по правилам проекта);
- открытый текст: бессмысленный набор символов, копипаста, мат без содержания (по политике модерации).

Что делать:
- помечать флагом `low_quality` и **исключать из индекса**, но хранить в сырье для аудита;
- не удалять физически без решения владельца исследования;
- порог «слишком быстро» фиксировать в брифе волны (например, < 20% медианы времени) — единый порог для всех волн одного продукта.

### 5.3. Дубли

- Один человек / один договор / один ID обращения — один ответ в аналитике (оставляем последний завершенный или первый — правило зафиксировать в брифе).
- При нескольких каналах — дедуп по сквозному ID.

### 5.4. Малые сегменты

- При **n < 30** по сегменту (ЖК, регион и т.д.) — публиковать только с пометкой **гипотеза / недостаточно данных**, без жестких управленческих выводов.

### 5.5. Голосования

- Считать только подтвержденные (SMS / одноразовая ссылка).
- После закрытия — заморозить базу; поздние ответы не принимать.

## 7. Типичные ошибки

| Ошибка | Что будет | Как правильно |
| --- | --- | --- |
| Забыли выключить ограничение повторов на тесте | Команда/заказчик не могут перепройти | Шаг 3 процесса |
| Забыли включить ограничение перед запуском | Дубли и накрутки | Шаг 8 процесса |
| Не зачистили тестовые ответы | Искажение NPS/CSI | Зачистка на шаге 8 |
| Включили IP-лимит для жителей ЖК | Много честных отсечено | Для ЖК — устройство / перс. ссылка, не IP |
| Рандомизировали шкалу NPS | Невалидная метрика | Шкалу 0–10 не рандомизировать |
| Включили таймер на длинном NPS | Случайные клики | Таймер выкл |
| Считают незавершенные в индексе | Занижение/шум | Только завершенные |
| Показывают лидерборд голосования в процессе | Бандвагон | Итоги — после закрытия |
| Запуск без согласования Голубевой Е. А. | Нарушение процесса | Шаг 7 обязателен |
| Жгут API-лимит 500/сутки | 429, дыры в витрине | Бюджет запросов, веб-хуки, дозаборка |

## 8. Краткая шпаргалка «блуждающие» ответы

В разговорной речи под «блуждающими» обычно имеют в виду одно из трех. В Testograf это разные настройки:

1. **Случайный порядок вопросов/ответов (рандомизация)** — см. §3.7.  
   Включать для равноправных списков; **выключать** для шкал NPS и логических последовательностей.
2. **Случайные быстрые клики респондента** — не «включается» в UI; **профилактика**: без таймера, нормальная длина, обязательные ключи; **лечение**: постобработка §5.2.
3. **Респондент «гуляет» по анкете и бросает** — помогают незавершенные (§3.6) + короче анкета + напоминания; в индекс — только завершенные.
